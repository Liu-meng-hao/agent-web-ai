# 页面真实图片接入可行性方案

## 1. 现状与结论

当前生成的页面里，所有视觉元素（插画、纹理、图标、背景）都由模型用 CSS 渐变、SVG、几何形状现画，**没有一张真实照片**。

根因不是模型“不会抓图”，而是整条链路被设计成**纯内联文本**：

| 环节 | 现状 | 位置 |
|---|---|---|
| 系统规则 | 成品页必须自包含，图片全部内联，禁止 `http(s)://` | `internal/cli/wire.go` 页面规则 |
| 工具描述 | 同上，`artifact_write` 明确要求图片内联 | `internal/tools/artifact.go` |
| 写后自检 | 外链资源（`img/script/link/...` 的 `src/href`）是**阻塞问题** | `internal/artifact/check.go` `externalResourcePattern` |
| 写入能力 | `artifact_write` 只接受 UTF-8 文本，无法写入二进制 | `internal/artifact/writer.go` |
| 抓取能力 | 没有图片搜索、没有下载工具；Playwright 只注册了 navigate/snapshot/screenshot/console/network/evaluate/resize/close | `config/mcp.yaml` |

结论：现在只能“自制图”，是规则 + 能力 + 数据格式三重限制的结果。

## 2. 设计不变量（方案必须遵守）

1. **预览可打开**：`/a/<slug>/` 下所有资源必须能由预览服务返回。
2. **离线可打开**：最终交付物如果继续坚持单文件/单目录可离线，就不能依赖远程 URL。
3. **不自造二进制**：模型不能输出 base64 大图，也不该由模型搬运二进制。
4. **安全边界**：素材来源必须在受控目录内，禁止 `..`、符号链接和任意扩展名。
5. **自检可判定**：每个方案都要说明 `check.go` 如何放行、如何拦截。

## 3. 候选方案对比

| 方案 | 做法 | 离线可用 | 版权风险 | 实现量 | 模型负担 | 主要风险 |
|---|---|---|---|---|---|---|
| **A. 本地素材库复制**（推荐） | 用户把图片放到共享素材目录，页面写 `assets/x.jpg`，writer 自动复制到页面目录 | 是 | 用户自担 | 中 | 低 | 素材要人工准备 |
| **B. 共享素材直链** | 页面直接引用 `/a/_shared/assets/x.jpg` | 否（离开预览即裂图） | 用户自担 | 低 | 低 | 破坏自包含，绝对路径已被自检拦截 |
| **C. 素材导入工具** | 新增 `asset_put`，把 workspace 里的图片二进制拷进页面 `assets/` | 是 | 用户自担 | 中 | 中（要决定拷哪些） | 需要新的工具与审批策略 |
| **D. 远程图片白名单** | 允许配置若干图片域名，自检对这些域名降级为非阻塞 | 否 | 高 | 低 | 低 | 离线裂图、隐私追踪、第三方失效 |
| **E. 浏览器截图取图** | 用 Playwright 截官网元素，存入素材目录再引用 | 是 | **高**（截图仍是他人素材） | 大 | 高 | 截图裁切不可控、版权与 ToS 风险 |

补充：B 与 D 都会让“发给别人/离线打开”失效；E 在技术上可行，但版权边界最模糊，不建议做成默认能力。

## 4. 推荐路径

分三期，先解决“有真实图片可用”，再解决“自动取图”。

### Phase 1：方案 A（本地素材库 + 自动复制）

**目录约定**

```text
data/artifacts/
├── _shared/
│   ├── tokens.css / base.css / gallery.html / charts.js
│   └── assets/                # 人工或团队维护的素材库
│       ├── hero-night.jpg
│       └── icons/arrow.svg
└── <slug>/
    ├── index.html             # 引用 assets/hero-night.jpg
    └── assets/hero-night.jpg  # writer 自动复制
```

**引用写法**

```html
<img src="assets/hero-night.jpg" alt="夜景">
```

**writer 行为**

1. 扫描 HTML 中所有 `src="assets/..."` / `url(assets/...)` 引用。
2. 到 `_shared/assets/` 找同名文件，复制到 `<slug>/assets/`。
3. 源文件缺失 → 阻塞错误，提示可用素材列表。
4. 已存在且内容一致 → 跳过；不一致 → 以最新为准并记录 manifest。

**自检规则调整**

- `assets/` 前缀的相对路径：源文件缺失 → 阻塞（现在是所有本地资源都只提示）。
- 其他相对路径保持提示级，避免多文件写入顺序误报。
- 外链规则不变，仍阻塞。

**系统提示与技能**

- 允许并推荐使用 `assets/` 相对路径。
- 明确“没有素材时不要编造图片文件名，改用 CSS/SVG”。
- 生成页面前可 `fs_list data/artifacts/_shared/assets` 看有哪些可用。

**验收标准**

- 放一张图到 `_shared/assets/`，提示“用 assets/xxx.jpg 做首屏”，生成页在预览与离线打开时都能显示。
- 引用不存在的素材 → `artifact_write` 明确报错，并列出可用文件。
- 页面目录内不放图时，行为与现在完全一致。

**工作量**：中等（writer 复制 + check 规则 + 提示词 + 测试）。

### Phase 2：方案 C（`asset_put` 工具）

适用场景：素材在 workspace 里，而不是共享素材库；或用户希望按页面隔离素材。

- 工具：`asset_put(source, slug, name)`，仅接受 `.png/.jpg/.jpeg/.webp/.svg/.ico`。
- 单文件 ≤ `artifact.max_file_kb`，总素材 ≤ 5MB，单页引用 ≤ 12 张。
- 源路径经 Jail 校验，禁止符号链接与目录穿越。
- 风险等级 `RiskWrite`，因目标在 artifact 根内，可走 `AutoApprover`。

**工作量**：中等偏大（新工具 + 审批 + 测试 + 文档）。

### Phase 3：方案 D（可选，默认关闭）

- 配置项：`artifact.remote_images.allowed_hosts`，默认空。
- 自检：白名单域名的图片从“阻塞”降为“非阻塞提示”。
- 预览页顶部显示“本页依赖外部图片，离线打开会裂图”。
- 默认关闭，只有明确接受离线失效时再开。

**工作量**：小，但风险最高，不建议作为默认能力。

## 5. 关键实现细节（Phase 1）

### 5.1 目录与复制安全

- 只在 `<slug>/assets/` 下写入，沿用现有 `withinDir` 校验。
- 复制源固定在 `_shared/assets/`，解析后必须仍在该目录内。
- 跳过符号链接；只允许白名单扩展名与已知 MIME。
- 单张图片超限直接拒绝，不做静默缩放。

### 5.2 预览服务

- 现有 handler 已按扩展名返回 Content-Type，图片放在页面目录即可直接访问。
- 需要补充验证 `svg/webp/avif` 的 MIME 是否被正确识别，缺失则补映射。

### 5.3 manifest 与清理

- manifest 增加 `assets: [{name, size, sha256}]`。
- `replace` 时清理由上一版引用、本版不再引用的素材，避免目录膨胀。
- 不做跨页面共享 cleanup，避免误删。

### 5.4 doctor

- 显示 `_shared/assets` 文件数与总大小。
- 抽查最近页面：引用存在性、总素材体积。
- 素材目录为空时给一条提示，而不是错误。

## 6. 验收用例（Phase 1）

1. 正常复制：引用 `assets/a.jpg`，文件出现在页面目录，预览 200。
2. 素材缺失：写 `assets/none.jpg` → 阻塞错误，消息含可用素材列表。
3. 路径穿越：写 `assets/../../config/agent.yaml` → 拒绝。
4. 非白名单扩展名：`assets/x.exe` → 拒绝。
5. 超限：单图超过 `max_file_kb` → 拒绝并提示压缩。
6. 离线：复制页面目录到别处，双击 `index.html` 仍能显示图片。
7. 回归：不含 `assets/` 引用的页面，自检结果与改动前一致。

## 7. 风险与未覆盖

- **版权**：方案 A/C 把素材责任交给使用者，项目只提供搬运能力，不做来源审核。
- **体积**：图片会让页面目录变大，`max_file_kb` 只约束单文件，不约束总量，需要 manifest 统计。
- **版本堆积**：素材复制后即使页面回滚也不会自动删除旧文件，需要后续 GC 策略。
- **方案 E 暂不做**：截图取图的版权与可维护性都差，等有明确授权场景再考虑。

## 8. 建议

先做 **Phase 1**：改动集中在 writer、check、提示词三处，不引入新工具，也没有版权判断负担，能立刻解决“页面只有自制图”的问题。

Phase 2 视使用频率决定；Phase 3 建议长期保持关闭。
